# stack-template

A full-stack starter: **FastAPI + SQLAlchemy + Alembic + Pydantic** backend,
**Next.js (App Router) + Tailwind** frontend, with working auth, Stripe
billing, streaming LLM chat with usage metering, and a two-service Railway
deployment.

Extracted from a production app; the boring parts are battle-tested.

## Architecture

The browser talks only to the Next.js origin. `next.config.ts` rewrites
`/api/*` to the FastAPI service, so the httponly session cookie stays
first-party, no CORS is involved, and the SSE chat stream passes through the
proxy. Public pages (landing, and any content routes you add) are
server-rendered and indexable — that's the SEO surface; the authed app pages
are client components.

The backend (`backend/app/`) is organized by layer, with strict placement
rules (see CLAUDE.md):

```
app/
├── core/       config, db session, auth wiring, rate limiting
├── models/     SQLAlchemy models — every module imported in __init__.py
├── schemas/    Pydantic input/output shapes (source of the generated TS types)
├── crud/       the only layer that touches the DB session
├── services/   business logic + external APIs (Stripe, Anthropic, email)
└── routes/     thin FastAPI routers: parse → call service → shape response
```

When a domain outgrows this, promote it to `app/modules/<domain>/` with the
same five folders nested inside.

## What's included

Everything below ships built-in and wired; [MODULES.md](MODULES.md) is the
menu of what's optional — spawning a project subtracts the modules it
doesn't need (teams/RBAC, chat, metering, billing) BEFORE the initial
migration is generated, so each project's schema and code contain only what
it uses.

- **Auth** — fastapi-users on the backend (`app/core/auth.py`): JWT in an httponly
  cookie, plus a bearer-token variant for a future mobile app. Frontend pages
  for register, login, forgot/reset password, and account deletion, all
  wired.
- **Sign in with Google** (flavor, dark until configured) — set
  `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` and the sign-in and sign-up
  pages grow a "Continue with Google" button
  (`app/services/oauth.py`, `components/GoogleSignIn.tsx`). Signing in with
  a Google address that already has a password account joins that same
  account. Unset: the button never renders and email + password is the only
  way in. Setup steps in `backend/.env.example`.
- **Email verification** (flavor, off by default) — set
  `REQUIRE_EMAIL_VERIFICATION=true` and new accounts get a verification
  email; unverified users can sign in but chat turns and checkout are
  gated, with a persistent verify banner + resend in the UI.
- **Teams / RBAC** (`app/models/org.py` … `app/core/rbac.py`, `/team`) —
  optional module: organizations with owner/admin/member roles, email
  invites with expiry, a `require_org_role(...)` route gate, and a team
  management page. Billing stays "owner pays" (the org inherits its
  owner's tier). Delete the module for solo-user apps.
- **Billing** (`app/services/billing.py`, `/account`) — Stripe Checkout + customer
  portal + the webhook that owns `users.tier`. All keys unset = payments dark
  (503s and honest UI copy), by design.
- **LLM chat** (`app/services/chat.py` + `/chat`) — optional module: streaming SSE
  chat with persisted conversations, free-tier turn caps with sign-in /
  upgrade nudges, refusal/error handling. Delete the module (both sides) if
  the project isn't conversational.
- **Usage metering** (`app/services/usage.py`, `app/routes/admin.py`) — one row per LLM call;
  monthly free-tier cap (per-user, per-IP for anonymous); superuser cost
  rollup endpoint.
- **SEO scaffolding** — static landing page, `metadata` in the root layout,
  `sitemap.ts`, `robots.ts` (authed routes disallowed).
- **Typed API bridge** — `frontend/lib/api-types.d.ts` is generated from the
  backend's OpenAPI schema; `lib/api.ts` derives its payload types from it,
  so a backend schema change becomes a frontend compile error. Regenerate
  after changing backend schemas:
  ```
  cd backend  && python scripts/export_openapi.py
  cd frontend && npm run generate:types
  ```
  (Commit the regenerated `.d.ts`; `backend/openapi.json` is a gitignored
  intermediate.)
- **Server-side session** — `frontend/lib/auth-server.ts` exposes
  `getUser()` for server components/route handlers (forwards the incoming
  cookies to the backend); `lib/useUser.ts` is the client-side counterpart.
- **Seeding** — `backend/scripts/create_superuser.py` creates or promotes a
  superuser (bypasses turn caps; can call `/api/admin/*`).
- **Living data-model diagram** — `docs/data-model.md` is a Mermaid ERD
  generated from `Base.metadata` (`backend/scripts/generate_erd.py`), with
  deletion behavior labeled on every edge. Regenerated by `/new-feature`
  after every migration; renders natively on GitHub. A projection of the
  code — never edited by hand, so it can't drift.
- **English-first workflow** — `BUILDING.md` is a plain-English phrasebook
  mapping product ideas to the stack's parts (for the non-engineer driving
  the project); CLAUDE.md tells the agent to propose that mapping in English
  before coding; the `/new-feature` skill is the end-to-end checklist every
  new concept flows through.
- **Ops** — per-service Dockerfiles + `railway.json`, docker-compose
  Postgres, Sentry (opt-in via env), loud production misconfiguration guards
  in `app/main.py`.

## Spawning a project

**The easy way**: open Claude Code in a new empty folder and paste the
filled-in prompt from [STARTER_PROMPT.md](STARTER_PROMPT.md) — the agent
runs all of the below, adapts to the machine (taken ports etc.), verifies
the running app, and then asks what to build.

**By hand:**

1. Click **Use this template** on GitHub (or copy the tree) and clone it.
2. `python rename.py <slug> "<Product Name>"` — replaces the `astoicmind` /
   `A Stoic Mind` sentinels and deletes itself.
3. Pick your modules (see [MODULES.md](MODULES.md)): solo or teams
   (orgs/RBAC), chat, billing, email verification. Remove what you don't
   need by following each module's removal checklist — do this BEFORE the
   next step, because the template ships with no alembic migrations and
   the initial migration is generated from whatever models remain.
4. Backend:
   ```
   cd backend
   python -m venv .venv && .venv/Scripts/activate   # or bin/activate
   pip install -r requirements.txt
   copy .env.example .env                            # then edit
   docker compose up -d
   python -m alembic revision --autogenerate -m "initial schema"
   python -m alembic upgrade head
   python scripts/create_superuser.py you@example.com <password>
   python -m uvicorn app.main:app --port 8000
   ```
5. Frontend: `cd frontend && npm install && npm run dev` — Next dev serves
   http://localhost:3000 and proxies `/api` to the backend (override the
   target with `API_URL`).
6. Deploy — one Railway project, two services (this exact sequence is
   validated end-to-end):
   ```
   railway init --name <project>
   railway add --database postgres
   railway add --service backend
   railway add --service frontend
   railway domain --service frontend        # note the URL for the vars below
   railway variables --service backend \
     --set 'DATABASE_URL=${{Postgres.DATABASE_URL}}' \
     --set 'AUTH_SECRET=<random 32+ chars>' \
     --set 'AUTH_COOKIE_SECURE=true' --set 'PORT=8000' \
     --set 'PUBLIC_BASE_URL=https://<frontend-domain>'
   railway variables --service frontend \
     --set 'API_URL=http://backend.railway.internal:8000' \
     --set 'NEXT_PUBLIC_SITE_URL=https://<frontend-domain>'
   railway up ./backend  --path-as-root --service backend  --ci
   railway up ./frontend --path-as-root --service frontend --ci
   ```
   Notes: `--path-as-root` is REQUIRED — a bare `railway up` uploads the
   repo root and the per-service Dockerfiles are never found. The backend
   needs no public domain (the frontend reaches it over private
   networking). `API_URL`/`NEXT_PUBLIC_SITE_URL` are consumed at BUILD time
   (declared as ARGs in the frontend Dockerfile) — redeploy the frontend
   after changing them. Add `ANTHROPIC_API_KEY` and the
   Stripe/Resend/Sentry keys to the backend service as those features go
   live.

Run alembic as `python -m alembic` (the exe entry point can't import `app`).
